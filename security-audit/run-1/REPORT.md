## 2. Security posture summary

The app is a small single-worker Next.js service whose security depends almost entirely on in-process state (two rate/lockout Maps in `lib/auth.ts` and `lib/rate-limit.ts`) plus deployment posture. Three themes emerged:

1. **In-process quota/heap integrity is attacker-controlled on pre-auth surfaces.** The shared rate limiter keys on a client-suppliable header into a Map that never evicts (medium, record below); the login-attempt ledger retains every distinct failed email for the process lifetime (low). Both are trivially scriptable at the compose-published direct-port deployment mode and are the two findings with the broadest reach.
2. **Login-control logic is weaker than its constants suggest.** The 5-strike lockout cannot actually engage against the sequential shape an attacker would use (medium — the sentinel state machine deletes its own counter every touch), and the only `/admin` authorization gate reads token existence but never the role claim (low — real invariant violation, inert data surface today).
3. **Six deployment/external-trust leads remain open.** The repo ships an upstream-spend path with no aggregate cap, a host-published Postgres port, a boot-time `npx` registry handoff that discards the lockfile-verified CLI, hardcoded seed admin fallbacks, an unvalidated `callbackUrl` echo whose only consumer is library-internal, and an unvalidated third-party feed URL bound straight into `href` anchors. Each is a repository-anchored root cause whose decisive remaining fact is a deployment, registry, provider, or browser-internal observation; all carry exact owner-observed checks and are listed separately below — they are leads, not findings.

No live environment was tested and no claim in this report rests on anything outside repository source plus bounded local reproduction.

### C1 — `lib/rate-limit.ts.checkRateLimit.attacker-keyed-unbounded-map` (medium)

- **Source location.** `app/api/news/route.ts:9-14,49-54` (entry + upstream spend) → `lib/rate-limit.ts:1-27` (module-global Map, per-key budget 10/60 s, no eviction, no cardinality cap); login call site `lib/auth.ts:81` keys on the first XFF segment.
- **Lower-trust principal.** Any unauthenticated HTTP client: the header value that becomes the limiter key arrives at the Next server from the wire (compose publishes the service port directly; whether any edge normalizes XFF in a given deployment is an owner fact, carried as a condition — the record's invariants hold whenever any client-controlled value reaches the server verbatim).
- **Bounded reproduction (sandbox, no network).** Verified local evidence: `agents/verifier-a/artifacts/observed-verifier-a-rate-limit.json` + `.mjs` (direct import of the actual target module, sha256 recorded in the record): same-key envelope 10/window; 60 distinct keys → 60/60 allowed; multi-hop `X-Forwarded-For: 1.2.3.4, <fresh>` consumes two different buckets across the two consumers' divergent parses; map growth 200k entries with `--expose-gc` confirming retained heap, no eviction at window rollover.
- **Conditions.** (i) client-supplied XFF/x-real-ip reaches the server (direct-port compose deployment does this; edge normalization would collapse the divergent-parse facet); (ii) `NEWSAPI_KEY` configured for the upstream-spend facet (the map-growth facet does not need it); (iii) `newsapi.org` plans are metered, so each escaped request is operator-billable.
- **Impact.** The intended budget (10/min per source) does not apply to any attacker that rotates a header value: quota escape converts into operator upstream spend (free for the attacker) and every novel key permanently retains a Map entry — a standing heap-growth handle on a single-worker server.
- **Priority rationale.** Overall = impact = medium: trivially scriptable (one header per request, fully anonymous), but each escape is a rate-limit violation + memory pressure, not direct data compromise; the actual downstream spend magnitude belongs to the adjacent needs-validation lead on aggregate spend.
- **Smallest source fix.** One shared key normalizer for both consumers (first comma segment, trim, length cap, IP-shape gate), a coarse overflow bucket once `MAX_KEYS=10_000` is reached, and eviction of expired entries before admission — exact code in `FINDINGS-DETAIL.md` (`normalizeIpKey`, `evictExpired`, modified `checkRateLimit`).

### C2 — `lib/auth.ts:24-39.lockout-sentinel-counter-collision` (medium)

- **Source location.** `lib/auth.ts:10,12,24-45` (constants + `isLockedOut`/`recordFailedAttempt`/`clearAttempts`) driven by `authorize()` at `lib/auth.ts:78-117`, mounted at `app/api/auth/[...nextauth]/route.ts:4-6`.
- **Lower-trust principal.** Any unauthenticated client able to reach the credentials callback REST surface, posing sequential wrong-password attempts against a reachable registered email (the seed's default admin is the obvious candidate).
- **Bounded reproduction (sandbox, no network).** `agents/verifier-d/artifacts/observed-lockout-state-machine.mjs` + `-run.txt`: functions copied verbatim from `lib/auth.ts:9-45` and `lib/rate-limit.ts:1-23`, zod/prisma/bcrypt replaced by fixed booleans at the same await points — observed serial sequence: `count` pinned at 1, threshold branch 0 executions, no `locked` result, while a burst-overlap counterpoint and the 15-minute expiry of a *posted* lock also behaved as the record states.
- **Conditions.** A registered user with non-empty hash and `isActive=true` reachable by email; single-process in-memory Map (Node's single-threaded loop cannot interleave the sync accessors mid-function — only cross-request overlap at the awaited prisma/bcrypt points escapes deletion); residual pacing bounded by the (C1-keyed) 10/min gate and bcrypt cost 12; next-auth v4 pinned, sequential per-attempt handling not independently executable here.
- **Impact.** The declared brute-force control contributes nothing on the serial shape: continued guessing can end in the password of the single-tenant admin/editor account with full admin/content control.
- **Priority rationale.** Medium — a security control that silently never engages plus a meaningful (gated) attacker path; below high because exploitation still requires winning the password guess, which the per-IP limiter (spoofability owned by C1) and bcrypt cost slow down.
- **Smallest source fix.** Gate the delete in `isLockedOut` on `lockedUntil > 0` (only real posted locks are time-bound) so the counter survives sequential `authorize()` calls and the `count >= 5` branch executes — exact code in `FINDINGS-DETAIL.md`.

### C3 — `middleware.ts:36-44.token-presence-only-gate` (low)

- **Source location.** `middleware.ts:36-44` (`withAuth` `authorized` callback evaluates `!!token`); role-bearing input `lib/auth.ts:134` (`token.role = user.role`); schema default `prisma/schema.prisma:19` (EDITOR); the only role-discriminating code `lib/auth-helpers.ts:25-33` has zero call sites (repo-wide grep).
- **Lower-trust principal.** Any authenticated non-ADMIN account (schema defaults every provisioned user to EDITOR).
- **Bounded reproduction.** `agents/verifier-g/artifacts/observed-gate-dispatch.mjs`/`.txt`: verbatim closure executed in-sandbox — `{role:"EDITOR"}` → authorized, role-less → authorized; impact containment is source-visible: `app/(admin)/admin` pages are static shells (no fetch/mutation) and `app/api/admin` has no files (the matched tree 404s).
- **Conditions / impact.** Attacker needs valid credentials for an active account; demonstrated impact is an authorization-invariant violation on inert surfaces at this commit — no data exposure claim is made.
- **Priority rationale.** Low: real gate defect, near-zero demonstrated blast radius today, but any future `/api/admin` route would inherit the gate silently.
- **Smallest source fix.** Bind the role claim at the single gate every `/admin` + `/api/admin` request already passes through (`token.role === "ADMIN"`, 403 otherwise) and add the regression case: EDITOR session must 403 while ADMIN passes.

### C4 — `lib/auth.ts:12-45.login-attempts-ledger-unbounded-cardinality` (low)

- **Source location.** Module-global `loginAttempts` Map (`lib/auth.ts:12`); pre-auth writes at `lib/auth.ts:104-105` (unknown/disabled/missing-hash) and `:111-112` (wrong password); deletions only on same-identifier expired-lock touch (`:27-29`) or successful login (`:44`, call site `:117`); no sweep/evict/TTL anywhere.
- **Lower-trust principal.** Any unauthenticated client — one schema-valid distinct email per retained entry, fully scriptable through the mounted credentials REST surface.
- **Bounded reproduction.** `agents/verifier-l/artifacts/observed-run-output.txt` (+ harness `.mjs`): growth phases 0/10k/50k/100k distinct emails → map size exactly equal at every phase, zero evictions; lifecycle: repeat failures add no cardinality, success-path clear removed exactly one identifier; end-state checks passed under the parent recipe.
- **Conditions / impact.** Single Node worker (`next start`) shares the Map; per-IP gate (`C1`-owned semantics) bounds the write rate, not retained cardinality; no availability/correctness/bypass effect claimed or demonstrated — slow guaranteed heap growth only.
- **Priority rationale.** Low: persistent, parallelizable, but low-and-slow (~MBs/day/IP at reproduced entry size) and resettable by process restart.
- **Smallest source fix.** Stamp `lastFailedAt`, add a passive amortized owner-side sweep invoked from `authorize()` that never evicts an active lock, and cap aggregate entries — must land together with the C2 fix (interplay note in the ledger: locked rows are retained by design; fixing the counter collision alone does not bound cardinality).

## 5. Hardening notes (non-finding source observations)

- **Editor/sanitizer wiring (latent).** `components/admin/editor.tsx:23-25` emits `getHTML()` raw and the repo's DOMPurify+JSDOM sanitizers (`lib/sanitize.ts:15,24`) have zero import sites today — attach `sanitizeHtml` at the first future persistence boundary.
- **CSP.** `script-src 'unsafe-inline' 'unsafe-eval'` with no nonce/hash is a standing regression hazard for the future render path; prefer nonce/hash. `img-src https: data: blob:` plus raw unoptimized feed `<img>` loads load any feed-supplied host in visitor browsers (deanonymization vector) — allowlist `urlToImage` scheme/host.
- **Coverage-claim posture (whole-of-surface).** Profile standard covered all 15 ledger units in scope `**`; out of repo view, only deployment/registry/provider/browser-internal facts (the NV set) are unassertible — they are carried as validation plans, not deferred coverage.
- **Middleware early-return paths** (`:13, :19, :23`) skip the security headers the fall-through branch sets — return headers uniformly; fold the `/api/admin` predicate into the authorized callback before any API tree lands.
- **Compose hardening.** Add `${VAR:?required}` guards for `POSTGRES_PASSWORD`/`NEXTAUTH_SECRET`; `DATABASE_URL` lacks `sslmode`; no networks/read_only/cap_drop/tmpfs/mem_limit/user overrides; `.dockerignore` should exclude `prisma/.env`, `*.pem`, `*.key`.
- **Supply-chain posture.** Seed-time and runtime contexts: `node:20-alpine` is mutable with no digest binding, `npm ci --no-audit --no-fund` suppresses advisory reporting at the only install point, no `engines` field, and boot-time `db push` makes app availability depend on registry reachability at every start.
- **Login schema literals.** `loginSchema` accepts up to 128-char passwords while bcryptjs drops bytes beyond 72 — cap or pre-hash; normalize `q` (`trim` + `min(1)`) and mirror the client cap; `newsQuerySchema`/`articleSchema.coverImage` lack a scheme allowlist (`z.string().url()` accepts any scheme — `.refine` to https: before wiring).
- **Information hygiene.** The unset-key 500 names the env var; `[SECURITY]` logs embed raw header strings; `NEWSAPI_KEY` in the URL joins the Next data-cache key (prefer header auth); upstream fetch has no `AbortSignal`; upstream error bodies are logged verbatim; auth logs contain emails/IPs (PII, no secrets); `PrismaAdapter` attached under JWT strategy leaves Account/Session/VerificationToken rows as dead surface.
- **Image flow.** `remotePatterns` grants are hostname-only and dead config today (all reachable `next/image` usages are unoptimized); restrict or delete grants when the image flow is next touched; Cloudinary grant pathnames interpolate operator env — set vars at build for determinism.
- **Slug collisions.** Accent/punctuation-colliding titles map to the same client-slice slug — derive/store a deterministic slug.

## 6. Positive source patterns observed

- All six feed anchors already carry `rel="noopener noreferrer"` (reverse-tabnabbing class closed pre-emptively).

- The Dockerfile builds with `npm ci` against the committed lockfile (the only integrity-verified install path), and `.gitignore` excludes `.env*` (including the template file after commit 84bc710).
